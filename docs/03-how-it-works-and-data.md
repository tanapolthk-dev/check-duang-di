# 03 · หลักการทำงานและแนวทางข้อมูล

เอกสารนี้อธิบายสิ่งที่โค้ดในเวอร์ชันต้นแบบ 0.1.0 ทำจริง อ้างอิงไฟล์ใน `src/`

## 1. ขั้นตอนตั้งแต่กรอกข้อมูลจนแสดงผล

```
[ฟอร์ม #/check]
   │ readForm()                          src/app.js
   ▼
validateBirth(input, today)              src/engine/validate.js
   │ ผิด → แสดงข้อผิดพลาดใต้ช่อง + สรุปด้านบน + โฟกัสสรุป
   │ ถูก ↓
(ถ้าติ๊ก "จำข้อมูล") saveRemembered()    src/ui/storage.js  → localStorage
   ▼
หน้า #/result สถานะ loading (อย่างน้อย 450 ms หรือ 150 ms ถ้าผู้ใช้ตั้งค่าลดการเคลื่อนไหว)
   ▼
buildReading(value, today)               src/engine/reading.js
   ├─ thaiAstroDay()  วันเกิดทางโหราศาสตร์ไทย      (ปฏิทิน + ธรรมเนียม)
   ├─ zodiacAnimal()  ปีนักษัตร                    (ปฏิทิน)
   ├─ tropicalSign()  ราศีแบบสากล                  (ปฏิทิน)
   ├─ buildLifeGraph() กราฟ 85 จุด อายุ 0–84        (จำลอง)
   └─ categories      4 หมวด ระดับ 1–5 + ข้อความ    (จำลอง)
   ▼
resultView() + lifeGraphSvg()            src/ui/views.js, src/ui/chart.js
   │ สำเร็จ → แสดงผล / ผิดพลาด → Error state + ปุ่มลองอีกครั้ง
```
ทั้งหมดทำงานในเบราว์เซอร์ ไม่มีการเรียกเครือข่าย (บังคับด้วย CSP `connect-src 'none'`)

## 2. วัตถุประสงค์ของข้อมูลแต่ละช่อง

| ช่อง | สถานะ | ใช้ทำอะไร | ถ้าไม่กรอก |
|---|---|---|---|
| วันที่ เดือน ปี พ.ศ. | จำเป็น | วันในสัปดาห์ ปีนักษัตร ราศี อายุปัจจุบัน และ seed ของแบบจำลอง | ส่งฟอร์มไม่ได้ |
| เวลาเกิด | ไม่บังคับ | เทียบกับเวลาพระอาทิตย์ขึ้นเพื่อหาวันเกิดทางโหราศาสตร์ไทย แยกพุธกลางวัน/กลางคืน และเป็นส่วนหนึ่งของ seed | ใช้วันตามปฏิทิน และกราฟแสดงช่วงไม่แน่นอน ±15 (แทน ±10) |
| ภูมิภาคที่เกิด | ไม่บังคับ | เลือกพิกัดอ้างอิงเพื่อคำนวณเวลาพระอาทิตย์ขึ้น และเป็นส่วนหนึ่งของ seed | ใช้พิกัดกรุงเทพฯ |
| จำข้อมูลบนเครื่องนี้ | ไม่บังคับ (ปิดไว้ก่อน) | เติมฟอร์มให้ครั้งหน้า | ไม่มีอะไรถูกเก็บ |

ไม่มีช่องชื่อ เพศ อีเมล หรือเบอร์โทร เพราะไม่จำเป็นต่อการคำนวณ (หลักเก็บข้อมูลเท่าที่จำเป็น)

## 3. Validation และการจัดการข้อมูลไม่ครบ

| กรณี | ข้อความที่ผู้ใช้เห็น |
|---|---|
| ไม่เลือกวัน/เดือน | เลือกวันที่เกิด / เลือกเดือนเกิด |
| ไม่กรอกปี | กรอกปีเกิดเป็น พ.ศ. 4 หลัก เช่น 2535 |
| ปีไม่ใช่ตัวเลข 4 หลัก | ปีเกิดต้องเป็นตัวเลข 4 หลัก เช่น 2535 |
| ปีอยู่ช่วง 1900–2100 | ปี 1992 ดูเหมือนเป็น ค.ศ. ลองกรอกเป็น พ.ศ. 2535 |
| ปีก่อน พ.ศ. 2443 | รองรับปีเกิดตั้งแต่ พ.ศ. 2443 เป็นต้นไป |
| ปีเกินปีปัจจุบัน / วันในอนาคต | ปีเกิดต้องไม่เกิน พ.ศ. … / วันเกิดต้องไม่เป็นวันในอนาคต |
| วันที่ไม่มีจริง (เช่น 31 ก.พ.) | วันที่ 31 ไม่มีในเดือนกุมภาพันธ์ ปี พ.ศ. … |
| ไม่กรอกเวลาและไม่ติ๊กข้าม | กรอกเวลาเกิด หรือเลือก "ไม่ทราบเวลาเกิด" |
| เวลาผิดรูปแบบ | เวลาไม่ถูกต้อง ใช้รูปแบบ ชั่วโมง:นาที เช่น 08:30 |

ข้อผิดพลาดแสดงทั้งใต้ช่อง (เชื่อมด้วย `aria-describedby`, ช่องที่ผิดมี `aria-invalid="true"`) และในกล่องสรุปด้านบนซึ่งรับโฟกัสทันที ค่าที่กรอกไว้ไม่หาย

## 4. หลักการสร้างผลลัพธ์และกราฟ

### ส่วนที่คำนวณจากปฏิทิน (ตรวจซ้ำได้)
- **วันในสัปดาห์** จาก `Date.UTC`
- **เวลาพระอาทิตย์ขึ้น** อัลกอริทึม Sunrise/Sunset ของ Almanac for Computers (1990) ใช้มุมจุดเหนือขอบฟ้า 90.833° และเวลา UTC+7 ทดสอบกับกรุงเทพฯ ได้ราว 06:40 ต้นมกราคม และราว 05:50 ปลายมิถุนายน
- **ปีนักษัตร** `(ปี ค.ศ. − 4) mod 12` (2020 = ชวด)
- **ราศีแบบสากล** ตามช่วงวันที่ tropical ที่ใช้ทั่วไป

### ส่วนที่เป็นธรรมเนียม/ความเชื่อ (ระบุป้าย "ความเชื่อ")
- นับวันใหม่เมื่อพระอาทิตย์ขึ้น และพุธกลางคืนตั้งแต่ 18:00
- สีประจำวันเกิด และลักษณะนิสัยตามวันเกิด (เขียนใหม่ด้วยถ้อยคำของทีม)

### ส่วนที่จำลอง (ระบุป้าย "จำลอง")
1. `seed = FNV-1a("ปี-เดือน-วัน|นาที|ภูมิภาค")`
2. ตัวสุ่มแบบกำหนดค่าได้ mulberry32 สร้างพารามิเตอร์: เฟสคลื่นหลัก (คาบ 12 ปี) แอมพลิจูด 16–21 คลื่นรอง (คาบ 5–9 ปี) แอมพลิจูด 6–10 และความแปรผัน ±2.5
3. ค่ารายปี = 50 + คลื่นหลัก + คลื่นรอง + ความแปรผัน → เกลี่ยด้วยค่าเฉลี่ยถ่วงน้ำหนัก 5 จุด → จำกัดช่วง 8–92
4. ช่วง: ≥ 62 = ลมส่ง, ≤ 38 = ชะลอ, ที่เหลือ = เก็บแรง
5. ช่วงความไม่แน่นอน ±10 (ทราบเวลาเกิด) หรือ ±15 (ไม่ทราบ)
6. ระดับหมวด: ภาพรวมใช้ค่าปีปัจจุบัน หมวดอื่นบวกค่าเบี่ยง ±15 ที่ขึ้นกับ seed+หมวด+ปี → แปลงเป็น 1–5 (`ceil(ค่า/20)`)
7. ข้อความเลือกจากคลัง 2 แบบต่อระดับต่อหมวด และเคล็ดลับ 3 แบบต่อหมวด

ผลที่ได้: ข้อมูลเดิมได้ผลเดิมในปีเดียวกัน ข้อความหมวดอาจเปลี่ยนเมื่อขึ้นปี พ.ศ. ใหม่

### การนำเสนอกราฟเพื่อไม่ให้สื่อว่าแน่นอน
- แสดงแถบความไม่แน่นอนรอบเส้นทุกจุด
- ใช้คำว่า "ระดับจำลอง" ไม่ใช้คำว่าดวงดี/ดวงร้าย
- ชื่อช่วงไม่ทำให้กลัว (ลมส่ง/เก็บแรง/ชะลอ)
- กล่องข้อความใต้กราฟบอกว่าไม่ใช่การคำนวณตามตำราใด
- มีตารางข้อมูลและแถบเลื่อนสำหรับผู้ที่มองกราฟไม่เห็น

## 5. สมมติฐาน ข้อจำกัด และการจัดการข้อผิดพลาด

สมมติฐาน: เวลา UTC+7, พิกัดระดับภูมิภาค, นักษัตรเปลี่ยน 1 ม.ค., กราฟอายุ 0–84 ปี
ข้อจำกัด: ไม่ใช่ตำราดั้งเดิม, เกิดต่างประเทศยังไม่ปรับเวลาพระอาทิตย์ขึ้น, คลังข้อความมีจำกัด, อายุเกิน 84 ปีจะใช้ค่าที่อายุ 84
ข้อผิดพลาด: `compute()` ครอบด้วย try/catch → Error state พร้อมปุ่มลองอีกครั้ง ข้อมูลที่กรอกยังอยู่; ถ้า localStorage ใช้ไม่ได้ (โหมดส่วนตัว/ถูกบล็อก) ทุกฟังก์ชันใน `storage.js` ล้มเหลวอย่างเงียบและแอปยังใช้งานได้; Clipboard API ใช้ไม่ได้ → ใช้วิธีสำรอง และถ้ายังไม่ได้ให้คำแนะนำคัดลอกเอง

## 6. ข้อมูลไปที่ไหน เก็บที่ไหน ใครเข้าถึง ลบอย่างไร

| ข้อมูล | ถูกส่งไป | จัดเก็บ | ใครเข้าถึงได้ | ลบอย่างไร |
|---|---|---|---|---|
| ข้อมูลเกิดในฟอร์ม | ไม่ถูกส่งไปที่ใด | ตัวแปรในหน่วยความจำของแท็บ | ผู้ใช้บนอุปกรณ์นั้น | ปิดแท็บหรือโหลดหน้าใหม่ |
| ข้อมูลที่เลือก "จำไว้" | ไม่ถูกส่งไปที่ใด | localStorage คีย์ `cdd:v1:remember` | ผู้ที่ใช้เบราว์เซอร์/โปรไฟล์นั้นบนเครื่องนั้น | ปุ่ม "ลบข้อมูลที่จำไว้" ในฟอร์มหรือหน้าความเป็นส่วนตัว, ยกเลิกติ๊กแล้วส่งฟอร์ม, หรือล้างข้อมูลเว็บไซต์ |
| ข้อความแชร์ | ไปยังแอปที่ผู้ใช้เลือกเอง | ไม่เก็บ | ผู้รับข้อความ | — (ไม่มีข้อมูลเกิด) |
| ข้อมูลการเชื่อมต่อ (IP, user agent) | ผู้ให้บริการโฮสต์ เช่น GitHub Pages | ตามนโยบายผู้ให้บริการ | ผู้ให้บริการโฮสต์ | ตามนโยบายผู้ให้บริการ — ทีมไม่มีสิทธิ์เข้าถึงแบบรายบุคคล |

ไม่มี backend ฐานข้อมูล บัญชีผู้ใช้ คุกกี้ analytics หรือโฆษณา จึงไม่มีค่าใช้จ่ายด้านจัดเก็บข้อมูล

## 7. ข้อมูลใดอยู่ใน GitHub และข้อมูลใดห้ามอยู่

**อยู่ใน GitHub ได้:** source code, CSS, ฟอนต์พร้อมใบอนุญาต, ไลบรารี QR (MIT), เอกสาร, ชุดทดสอบ, workflow สำหรับ deploy, `.env.example` (ไม่มีค่าจริง)

**ห้ามอยู่ใน GitHub:** วัน/เวลา/สถานที่เกิดของผู้ใช้จริง, ข้อมูลบัญชี, ภาพหน้าจอที่มีข้อมูลผู้ใช้จริง, log ที่มีข้อมูลผู้ใช้, ไฟล์ `.env` จริง, API key/token/secret ทุกชนิด

ข้อมูลตัวอย่างในชุดทดสอบเป็นวันที่สมมติ ไม่ใช่ของบุคคลจริง และ `tests/e2e/output/` (ภาพหน้าจอจากการทดสอบ) ถูกยกเว้นใน `.gitignore`

## 8. การป้องกัน API key, secret, token และข้อมูลส่วนบุคคล
1. แอปไม่ต้องใช้ secret ใด ๆ — ไม่มีอะไรให้หลุด
2. `.gitignore` กัน `.env*` (ยกเว้น `.env.example`), `*.pem`, `*.key`, `user-data/`, ผลทดสอบ
3. `scripts/check-secrets.mjs` สแกนหารูปแบบ token, private key, อีเมล และเลขคล้ายบัตรประชาชน รันได้ด้วย `npm run check:secrets` และรันอัตโนมัติใน GitHub Actions ก่อน deploy
4. Content-Security-Policy จำกัดให้โหลดเฉพาะไฟล์จากเว็บเดียวกัน และห้ามสคริปต์เชื่อมต่อเครือข่าย ลดความเสี่ยงที่ข้อมูลจะถูกส่งออกแม้มีโค้ดที่ไม่ตั้งใจ
5. `<meta name="referrer" content="no-referrer">` ไม่ส่ง URL ของหน้าไปยังเว็บอื่นเมื่อผู้ใช้คลิกลิงก์ออก
6. ถ้าวันหนึ่งต้องมี backend: secret ต้องอยู่ฝั่งเซิร์ฟเวอร์หรือ GitHub Actions Secrets เท่านั้น ห้ามใส่ใน `src/` เพราะทุกไฟล์ฝั่งหน้าเว็บมองเห็นได้สาธารณะ
