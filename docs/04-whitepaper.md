## 1. บทสรุปผู้บริหาร

เช็คดวงดิ๊เป็นเว็บแอปเช็คดวงจากวันเกิดที่ใช้ได้ฟรีผ่านลิงก์หรือ QR code ผู้ใช้กรอกวันเกิด (เวลาและสถานที่เกิดไม่บังคับ) แล้วได้ผล 5 หมวด คือ ภาพรวม ความรัก การงาน การเงิน และจังหวะชีวิต พร้อมกราฟรอบ 12 ปี

จุดยืนของผลิตภัณฑ์มี 3 ข้อ: **จบเร็ว โปร่งใส และข้อมูลอยู่กับผู้ใช้**
- [ข้อเท็จจริง] การประมวลผลทั้งหมดอยู่ในเบราว์เซอร์ ไม่มี backend ไม่มีฐานข้อมูล ไม่มีตัวติดตาม และหน้าเว็บตั้ง Content-Security-Policy ห้ามสคริปต์เชื่อมต่อเครือข่าย
- [ข้อเท็จจริง] ผลลัพธ์ทุกส่วนติดป้ายว่ามาจาก "ปฏิทิน" "ความเชื่อ" หรือ "จำลอง"
- [ข้อเท็จจริง] เวอร์ชันปัจจุบันเป็นต้นแบบเพื่อความบันเทิง ส่วนคำทำนายและกราฟสร้างจากแบบจำลองที่ทีมออกแบบเอง ไม่ใช่ตำราโหราศาสตร์ดั้งเดิม
- [ข้อเท็จจริง] ผ่านการทดสอบอัตโนมัติ unit 17 กรณีและ end-to-end 18 กรณีบน Chromium ในสภาพแวดล้อมพัฒนา (รายละเอียดใน `05-test-plan-and-report.md`)
- [ข้อเท็จจริง] Deploy บน GitHub Pages แล้วเมื่อ 8 ต.ค. 2569 ที่ https://tanapolthk-dev.github.io/check-duang-di/ จาก repository https://github.com/tanapolthk-dev/check-duang-di (สาธารณะ)

## 2. วิสัยทัศน์และปัญหาที่ต้องการแก้

**วิสัยทัศน์:** ให้การดูดวงเป็นเครื่องมือชวนคุยกับตัวเองที่สนุก อ่านง่าย และเคารพความเป็นส่วนตัว

**ปัญหาที่สังเกตจากการศึกษาเว็บอ้างอิง** ([ข้อเท็จจริง] จากการตรวจหน้าเว็บ 8 ต.ค. 2569 ดู `01-reference-study.md`)
1. พอร์ทัลขนาดใหญ่มีบริการจำนวนมากในหน้าเดียว ผู้ใช้ใหม่ต้องเลือกเองว่าจะเริ่มจากตรงไหน
2. บางเว็บขอข้อมูลที่ไม่จำเป็นต่อการคำนวณ เช่น ชื่อ-สกุล และโหลดเครื่องมือติดตาม
3. ผลลัพธ์มักไม่แยกให้เห็นว่าส่วนใดคำนวณจากปฏิทิน ส่วนใดเป็นความเชื่อ

[สมมติฐาน] ผู้ใช้กลุ่มใหญ่ต้องการคำตอบเร็วและเข้าใจง่าย มากกว่าความครบถ้วนของศาสตร์

## 3. กลุ่มผู้ใช้และความต้องการ

กลุ่มเป้าหมายคือผู้ใช้ทั่วไปที่สนใจดูดวงและการสำรวจตนเอง ผลิตภัณฑ์ออกแบบให้เป็นมิตรกับคนหลายวัย และไม่ระบุช่วงอายุบนหน้าเว็บ

| กลุ่ม (สมมติฐาน) | ความต้องการ | สิ่งที่ผลิตภัณฑ์ตอบ |
|---|---|---|
| ผู้ใช้ขาจร เห็นลิงก์จากโซเชียล | ลองเร็ว ไม่ต้องสมัคร | ฟอร์ม 1 หน้า ช่องจำเป็นมีแค่วันเกิด |
| ผู้ใช้ที่ห่วงความเป็นส่วนตัว | รู้ว่าข้อมูลไปไหน | หน้าความเป็นส่วนตัวแบบตาราง ไม่มีบัญชี |
| ผู้ใช้ที่ไม่ทราบเวลาเกิด | ยังใช้งานได้ | ข้ามเวลาเกิดได้ ระบบบอกผลกระทบ |
| ผู้ใช้ที่ชอบแชร์ | แชร์สนุก ๆ โดยไม่เผยวันเกิด | ข้อความแชร์มีแค่ชื่อช่วงจังหวะชีวิต |
| ผู้ใช้โปรแกรมอ่านหน้าจอ/คีย์บอร์ด | ใช้งานได้ครบ | semantic HTML, ตารางแทนกราฟ, โฟกัสชัด |
| ผู้ใช้สูงวัย | ตัวอักษรอ่านง่าย ปุ่มใหญ่ | ฐานตัวอักษร 17px ปุ่มสูง 48px |

## 4. คุณค่าของผลิตภัณฑ์
1. **เร็ว** — จากหน้าแรกถึงผลลัพธ์ใช้ 3 ขั้นตอน
2. **ซื่อตรง** — ป้ายที่มาทุกผล และคำเตือนว่าไม่ใช่คำแนะนำทางการแพทย์ การเงิน กฎหมาย
3. **เป็นส่วนตัวโดยออกแบบ** — ไม่มีที่ให้ข้อมูลรั่ว เพราะไม่มีการส่งข้อมูลออก
4. **ไม่ทำให้กลัว** — ชื่อช่วงกราฟและข้อความเขียนเชิงชวนทบทวน ไม่ฟันธง มีชุดทดสอบตรวจคำต้องห้าม
5. **ฟรี** — static site โฮสต์บนบริการแผนฟรีได้

## 5. User journey และประสบการณ์ใช้งาน

```
พบลิงก์/สแกน QR → หน้าแรก → [เริ่มเช็คดวง] → ฟอร์ม → (ตรวจข้อมูล) → Loading → ผลลัพธ์
                                                  ↘ ข้อผิดพลาด: สรุปด้านบน + ใต้ช่อง
ผลลัพธ์ → อ่าน 5 หมวด → เลื่อนดูกราฟ → แชร์ข้อความ → (ครั้งหน้า) ฟอร์มเติมให้ถ้าเลือกจำไว้
```

รายละเอียดจุดสัมผัส
- **หน้าแรก:** ชื่อแบรนด์ใหญ่ วงแหวน 12 ช่อง ประโยคบอกประโยชน์ และคำยืนยันเรื่องฟรี/ความเป็นส่วนตัวก่อนกด
- **ฟอร์ม:** ป้าย (จำเป็น)/(ไม่บังคับ) พร้อมเหตุผลของแต่ละกลุ่มช่อง ตรวจปี ค.ศ. ที่กรอกผิดและแนะนำค่า พ.ศ. ให้
- **สถานะ:** Loading แสดงสั้น ๆ, Empty state เมื่อเปิดหน้าผลโดยตรง, Error state พร้อมลองอีกครั้ง, หน้าไม่พบ
- **ผลลัพธ์:** แถบลิงก์ไปยังหมวด, ระดับ 1–5 พร้อมคำอธิบายเป็นข้อความ, เคล็ดลับเล็ก ๆ, กราฟ แถบเลื่อน และตาราง
- **กลับมาใช้งาน:** ตัวเลือก "จำข้อมูลบนเครื่องนี้" (ปิดไว้ก่อน) — [ข้อเท็จจริง] ผลลัพธ์ไม่ถูกใส่ใน URL จึงต้องคำนวณใหม่ทุกครั้ง ซึ่งเร็วเพราะทำในเครื่อง

## 6. สถาปัตยกรรมระบบ

```
┌────────────── เบราว์เซอร์ของผู้ใช้ ──────────────┐
│ index.html (CSP: self only, connect-src none)   │
│   ├─ assets/css, assets/fonts (โฮสต์เอง)          │
│   └─ src/app.js  ── router (hash) + state        │
│        ├─ engine/ validate, calendar, reading,   │
│        │          random, content  (ฟังก์ชันบริสุทธิ์) │
│        ├─ ui/ views, chart(SVG), link(QR),       │
│        │      storage(localStorage), dom         │
│        └─ vendor/qrcode.mjs (MIT)                │
└─────────────────────────────────────────────────┘
          ▲ ดาวน์โหลดไฟล์ static เท่านั้น
┌─────────┴──────────┐      ┌───────────────────────┐
│ Static hosting      │◀─────│ GitHub repo + Actions │
│ (แนะนำ GitHub Pages) │ deploy│ test → secret scan →  │
└────────────────────┘      │ upload artifact        │
                            └───────────────────────┘
```

[ข้อเท็จจริง] เลือก HTML/CSS/JavaScript แบบ ES modules โดยไม่มีขั้นตอน build และไม่มี dependency ตอนรัน (นอกจากไลบรารี QR ที่ฝังไว้) เหตุผล: ดูแลต่อง่าย ไม่มีแพ็กเกจให้อัปเดตตามความปลอดภัย deploy บน static hosting ได้ทันที และให้คนที่เพิ่งเริ่มเขียนเว็บอ่านโค้ดเข้าใจ

## 8. กราฟหรือไทม์ไลน์ชีวิต
- แกนนอน: อายุ 0–84 ปี (7 รอบ รอบละ 12 ปี) เส้นแบ่งทุก 12 ปี
- แกนตั้ง: ระดับพลังจำลอง 0–100 แบ่งพื้นหลังเป็น 3 ช่วง (ลมส่ง ≥ 62, เก็บแรง, ชะลอ ≤ 38)
- เส้นสีครามบนแถบความไม่แน่นอน ±10 หรือ ±15 จุดดาวเรือง "ตอนนี้"
- แถบเลื่อนอายุ: ใช้ได้ทั้งเมาส์ นิ้ว และคีย์บอร์ด แสดงคำอธิบายเป็นข้อความ
- ตารางทุกปีใน `<details>` สำหรับโปรแกรมอ่านหน้าจอหรือผู้ที่ต้องการตัวเลข
- [ข้อเท็จจริง] กราฟวาดด้วย SVG ตามความกว้างจริงของจอ จึงไม่มีตัวหนังสือเล็กเกินอ่านบนมือถือ และทดสอบแล้วว่าไม่ล้นจอที่กว้าง 390px

## 9. การจัดเก็บและปกป้องข้อมูล
- [ข้อเท็จจริง] ข้อมูลเกิดอยู่ในหน่วยความจำของแท็บ และหายเมื่อปิดหรือโหลดหน้าใหม่
- [ข้อเท็จจริง] เก็บใน localStorage เฉพาะเมื่อผู้ใช้ติ๊ก "จำข้อมูลบนเครื่องนี้" ลบได้ 3 ทาง
- [ข้อเท็จจริง] ไม่มีข้อมูลผู้ใช้ใน GitHub — GitHub ใช้เก็บเฉพาะ source code และเอกสาร
- [ข้อเท็จจริง] ทดสอบอัตโนมัติยืนยันว่าเมื่อไม่ติ๊กจำข้อมูล localStorage, sessionStorage และ cookie ว่างเปล่า และไม่มีคำขอเครือข่ายไปยังโดเมนอื่น
- [ข้อเท็จจริง] ผู้ให้บริการโฮสต์ยังเห็นข้อมูลการเชื่อมต่อทั่วไป (เช่น IP) ตามนโยบายของผู้ให้บริการ ซึ่งแจ้งไว้ในหน้าความเป็นส่วนตัว
- สาระครบถ้วนอยู่ใน `03-how-it-works-and-data.md` หัวข้อ 6–8

## 11. Accessibility และการออกแบบที่ครอบคลุม
- [ข้อเท็จจริง] ภาษา `lang="th"`, landmark (header/nav/main/footer), ลิงก์ข้ามไปเนื้อหาหลัก, ลำดับหัวเรื่องถูกต้อง
- [ข้อเท็จจริง] ทุกช่องมี label, คำอธิบายเชื่อมด้วย `aria-describedby`, ข้อผิดพลาดใช้ `aria-invalid` และกล่องสรุป `role="alert"`

## 12. วิธีเผยแพร่และเปิดให้ใช้งานฟรี

**ช่องทางที่แนะนำ: GitHub Pages ผ่าน GitHub Actions** (ไฟล์ `.github/workflows/pages.yml` เตรียมไว้แล้ว)

[ข้อเท็จจริง] เงื่อนไขที่ตรวจจากเอกสาร GitHub เมื่อ 8 ต.ค. 2569: ใช้ได้กับ repository สาธารณะในแผน GitHub Free, ขนาดเว็บที่เผยแพร่สูงสุด 1 GB, แบนด์วิดท์ soft limit 100 GB ต่อเดือน, การ deploy ต้องเสร็จภายใน 10 นาที และ GitHub Pages ไม่ได้มีไว้สำหรับร้านค้าออนไลน์หรือ SaaS เชิงพาณิชย์ เงื่อนไขเหล่านี้อาจเปลี่ยนได้ ควรตรวจซ้ำก่อนใช้งานจริง

[สมมติฐาน] ขนาดแอปราว 300 KB ต่อการเปิดครั้งแรก แบนด์วิดท์ 100 GB จึงรองรับการเปิดครั้งแรกได้หลักแสนครั้งต่อเดือน (คำนวณคร่าว ๆ ไม่รวมแคช)

ข้อควรระวัง: เมื่อเริ่มมีสปอนเซอร์หรือรายได้ ให้ตรวจข้อกำหนดของ GitHub อีกครั้ง หากไม่เหมาะ ให้ย้ายไปบริการ static hosting อื่นที่อนุญาตการใช้เชิงพาณิชย์ โดยตรวจเงื่อนไขแผนฟรี ณ วันที่ย้าย ซึ่งทำได้ง่ายเพราะแอปเป็นไฟล์ static ล้วน

**สถานะ:** [ข้อเท็จจริง] เผยแพร่แล้วที่ https://tanapolthk-dev.github.io/check-duang-di/ ผ่าน GitHub Actions (workflow ทดสอบ → สแกน secret → deploy) เมื่อ 8 ต.ค. 2569 ไฟล์ QR สำหรับสื่ออยู่ที่ `assets/qr/`

**ลิงก์และ QR:** หลัง deploy หน้า "เปิดบนมือถือ" แสดงปุ่มคัดลอกลิงก์และ QR อัตโนมัติเมื่อโฮสต์บน `*.github.io` หรือเมื่อกำหนด `publicUrl` ใน `src/config.js` ระบบจะไม่สร้าง QR ไปยัง URL ที่ยังไม่มีจริง
